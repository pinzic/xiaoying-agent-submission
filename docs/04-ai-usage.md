| 环节 | 谁做的 | 说明 |

`data/docs/*.md` 原文抽取并经 `verify_answer` 校验。

## 2. 个人贡献（人工决策清单）

1. **拒绝"版本新者优先"**：D02 比 D01 新，但正文没写替代/废止。最初实现想按生效日期自动选新的，
   本人判断这违反题目"不能擅自回答 15 天"的要求，改为只输出提示、仍要求用户确认。
2. **确定"优先条款不能单独定分"**：发现"年假有几天？"被实习生制度抢答后，要求把定分条件收紧为
   "适用范围命中 + 优先条款"，否则回到追问。
3. **确定引用校验的严格度**：选择"宁可 failed 也不输出无法逐字核验的引用"，放弃"概括式引用"的便利。
4. **确定不做的事**：不做 Web UI、不做多 Agent、不接向量库，把时间留给检索与冲突处理。
5. **审核合成语料**：确认 D01/D02 的表述确实"没给适用范围与优先级"，避免语料本身泄露答案。
6. **要求失败原因如实分类**：排查中发现空检索词被报成"服务超时"，判定这是比失败本身更糟的错误
   （会误导运维方向），要求参数错误与上游故障分开处理，并补 CLI 层校验。

## 3. 验证方式（可复现）

```bash
# 1. 全量测试
python -m unittest discover -s tests -v        # 39 passed
python -m scripts.run_ablation                 # 6 组文档扰动实验，不符预期则退出码 1

# 2. 逐场景跑 CLI，核对状态与引用
python -m src.cli --question "报销期限是多久？"          # needs_clarification
python -m src.cli --question "公司可以帮我办理日本签证吗？"  # insufficient_info
python -m src.cli --question "报销期限是多久？" --fault search_docs:2   # failed

# 3. 抽查引用是否逐字存在（以 case1 为例）
python - <<'PY'
import json, pathlib
out = json.load(open('examples/case1_clear_answer/output.json', encoding='utf-8'))
doc = pathlib.Path('data/docs/D04.md').read_text(encoding='utf-8')
for c in out['citations']:
    print(c['doc_id'], c['quote'] in doc)
PY

# 4. 文档替换后答案是否变化
python -m unittest tests.test_robustness -v
```

验证结果：39/39 通过；9 组 examples 的状态与预期一致；抽查引用均能在原文中逐字找到；
扰动实验 6/6 符合预期（删除/改数值/改条款后答案与动作均随之改变）。

## 4. 本人补充的信息

- **实际投入时长**：约 3 小时（在题目建议的投入范围内），分配大致为
  语料与规则设计 ~30min、核心链路实现 ~60min、测试与验证材料 ~40min、文档 ~30min、第二轮排查 ~20min。
- **使用的工具**：对话式编程助手 **WorkBuddy**（即本会话），用于生成/修改代码、补测试、起草文档。
  **未使用**其他 AI 工具（没有用其他对话模型参与方案讨论，也没有用编辑器内 AI 补全）。
  底层模型版本以客户端为准，未单独记录——本次结论不依赖特定模型版本（所有 trace 由离线 Mock 规划器生成）。
- **本人额外手改的代码位置**：**无**。全部代码由 AI 生成后，经本人运行、阅读输出、反馈缺陷并迭代；
  本人没有在编辑器里手工改写过任何一行代码。本人的贡献集中在判断与验收上（见 §2）。
