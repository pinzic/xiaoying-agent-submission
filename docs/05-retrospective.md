# 05 · 复盘：最难的问题、收获与下一步

## 1. 最难的问题

### 1.1 "什么才算有资格定分"——冲突处理的边界

题目给的参考实例很明确：D01 30 天、D02 15 天、都没写适用范围和优先级 → 必须追问。
但真实实现里，"有没有依据"是个连续谱：

- 版本日期更新，算不算依据？
- 一份制度写了"以本规定为准"，算不算依据？
- 一份制度的适用范围是"实习生"，而问题没说明提问人身份，算不算依据？

我最初把"有优先条款"当依据，结果"年假有几天？"被《实习生管理规定》抢答成"不享受"——
这正是题目最忌讳的"擅自选一个"。最后的规则是：**定分需要"适用范围命中"这个锚点**，
优先条款只能加强、不能单独成立；版本日期只作为提示写进回答。这条边界比写代码本身难。

### 1.2 检索门槛：宽了答非所问，严了改写问题召不回

"我想问下旅游补贴"因为命中"补贴"被召回《加班与调休管理规定》，Agent 会一本正经回答加班补贴——
比"不知道"更糟。但把门槛简单调高，"加班换来的补休，最晚多久要休掉？"这类口语改写又会掉出召回。
最终用"覆盖率 + 扩展后命中词数"的双门槛，并给同义词表兜底，才同时满足两类用例。

### 1.3 引用"看起来对"和"确实对"

追问话术里列了 5/10/15 天，但只引用了 5 天那一句——人读起来毫无问题，程序校验直接报错。
这件事让我确认：引用校验必须做成**代码闸门**（逐字子串 + 数字溯源），不能靠提示词或人工目测。

### 1.4 第二轮排查：跑通了不等于说对了

链路全绿、28 个测试通过后，我又回头逐个场景试探边界，又揪出三类问题：

- **分档取值按字符串排序**：年假 5/10/15 被排成"10 天、15 天、5 天"。答案的数值、引用全都正确，
  只是顺序不对——这类缺陷不会让任何测试变红，只有把输出**读一遍**才会发现；
- **空语料库除零**：`avg_len = total / len(chunks)`，文档目录为空时直接崩；
- **把参数错误说成服务故障**：空检索词触发 `bad_arguments`，却被当成 `upstream_timeout` 重试，
  最终报"检索工具不可用（upstream_timeout）"。状态机没错、也没有编造答案，
  但**失败原因写错了**——这比失败本身更糟，因为评审/运维是照着 `gaps` 定位问题的。

共同点是：三个都不影响"happy path"，也不会被"断言输出等于某字符串"的测试发现。
修完之后我把它们各自固化成测试，并在排查时养成了一个习惯——**每个用例不只断言状态，
还要读一遍 `answer` 全文**，看它是否像人该说的话。

## 2. 学习收获

1. **Agent 的难点不在循环，在"什么时候停"**：工具调用本身很好写，难的是定义"证据够了"的标准
   （读到原文、比对过冲突、引用能逐字核验）。
2. **把不确定性显式化**：`insufficient_info` / `needs_clarification` / `failed` / `incomplete` 四个非成功状态
   比一个 `answer` 字段更能体现系统是否可靠。
3. **规则 + 模型的边界**：deterministic 的部分（取值抽取、冲突比对、引用校验）交给代码，
   语义理解的部分交给模型，两者的接口用结构化数据（claims / conflicts / citations）固定下来。
4. **测试要对着"审核要点"写**：替换文档内容看答案是否变化，比单纯断言"输出等于某字符串"更能暴露脆弱点。
5. **文档里的数字要由测试守护**：召回率写"9/10"而实测是 10/10，是因为它是我手工跑出来的、
   没有进 CI。现在这条进到 `test_recall_benchmark_top1`，改检索就会暴露。

## 3. 如果继续做（下一步）

1. **接真实模型并做小规模评测**：用 30 条标注问题（含 10 条冲突、5 条资料外、5 条改写）跑 `--planner llm`，
   人工核对引用准确率与"该追问时是否追问"，把结果补进 `docs/03`。
2. **检索升级**：BM25 + 向量混合召回；对同义改写用 embedding 兜底，减少对同义词表的依赖。
3. **冲突抽取从规则换成正则 + LLM 双跑**：LLM 抽 claim、规则做校验，人工抽检 50 条。
4. **多文档冲突（>2 篇）与传递性**：目前只做两两比对，三份以上互相矛盾时的话术需要重新设计。
5. **权限与时效**：不同部门可见制度不同、制度过期失效（`effective_date` + `expired_date`）应参与检索过滤。

## 4. 用时与未完成项

- **实际用时**：约 3 小时（含语料与规则设计、核心链路实现、测试与验证材料、五份文档，以及第二轮排查）。
- **未完成 / 主动放弃**：
  - 真实 LLM 的实测记录（无可用密钥）——代码路径已实现，但没有真实模型 trace；
  - Web 界面与线上部署（题目说明非必需，主动放弃）；
  - 三篇以上文档的冲突归并（只做两两比对）；
  - `MockPlanner` 只取得分最高的 2 篇候选，第 3 篇及以后的潜在冲突会被漏掉（真实模型规划器无此限制）；
  - 会话状态持久化（`history` 由调用方传入）。
